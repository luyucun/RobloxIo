# 开发顺序规划

> 本文给出当前阶段目标、依赖关系和最小验证目标。每完成一阶段更新本文并写开发记录。

## 阶段 0：工作流接入收尾（当前，2026-09-29 启动）

目标：把合成陀螺的标准工作流在本项目跑通闭环。

1. 用户启动桥：双击 `tools\start-mcp-bridge.cmd`（端口 58747）保持窗口。
2. 打开本项目 Studio 窗口 → `get_place_info` 读回 gameId → 回填 `.studio-mcp.json`、`项目配置清单.md`、`Studio操作规范.md`。
3. `tools/patch-mcp-plugin.ps1` 的 DEFAULT_MAP 加入本项目路由 → 运行补丁 → 重启 Studio 窗口。
4. `Assert-StudioProject` 三方核对通过；从其他项目端口指向 58747 被拒。
5. 端口注册表状态更新为已接入。

最小验证目标：MCP 闸门全绿 + `rojo sourcemap default.project.json` 可解析。

## 阶段 1：P0 安全修复（最高优先，见 BUG清单与解决方案.md）

按顺序修复并逐项登记开发记录：

1. **P0-1 死亡绕过免费复活**：`TryEnterArena`/`_onRequestJoinBattle` 加 Alive 校验。改动前先在需求文档/架构文档明确"死亡玩家不可经 Portal 重入战场"。
2. **P0-2 小怪令牌刷经验**：击杀上报强制 `Active == true` + 已激活令牌上限 + 激活纳入限速 + 激活-击杀最小时间差。
3. **P0-3 七日登录/复仇/保级付费丢发**：ProcessReceipt 入口补"数据已加载"守卫（对照 SkinService 范式）。
4. **P0-4 收据幂等台账**：所有 Robux 发货路径接入 PurchaseId 持久化台账 + `_processReceipt` 整体 pcall。

最小验证目标：每个 P0 有针对性验证（服务端拒绝路径实测/模拟收据重投），并补进验证与验收清单的手动验证表。
